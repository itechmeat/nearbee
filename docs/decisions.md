| D-001 | 2026-11-09 | The hackathon product is the adapter (Nearbee), not a mascot app and not single agents. | D-007 | 2026-11-09 | Privacy tiers plain, attested, blind; validated at publish time from apb profiles, connectors and decision providers; descriptions generated, not typed. **The attested tier's v1 evidence is run-level attestation disclosure**, labelled as such; per-response proof through the signed script step of D-008 where a playbook has one. | The listing is part of the contract; only shown claims may be promised. apb's `environment` is not a sandbox and run-level reports do not bind responses (Codex review, findings 4 and 9). |
| D-008 | 2026-11-09 | Model choice stays in apb profiles; Nearbee ships profile templates and validates them. **Approved exception**: in `doc-digest-private` the final digest generation is one bounded Cloud API call from a trusted `script` node that keeps the exact bytes and fetches the `provider_tee` response signature; the rest of the pipeline runs through profiles with run-level disclosure. | D-009 | 2026-11-09 | Listings belong to the owner's market account; self-registration is used only for throwaway tests. | Self-registered agents cannot withdraw and stay out of Discover. |

| D-012 | 2026-11-09 | Buyer data never enters apb's learning features; market playbooks run in a dedicated apb project with discover, memory, corrections and judge-example capture off; exact settings recorded once verified. | Job Terms 7.1: use only for the job, no training. | D-018 | 2026-11-09 | **v1 pricing is the owner's explicit price and SLA per listing.** Limits are optional. The adapter protects the owner without configuration: a per-hire cost ceiling derived from the price (run budget plus wall-clock limit, decline with full refund on overrun) and one cheap scope check before start; both can be switched off per listing. Auto-pricing from run observations (own p90, rework reserve, decimal rounding) is v1.1. | Owner 2026-11-09: do not fuss over limits; Nearbee cannot know what an arbitrary playbook can handle, only its author can. apb exposes medians and ranges only (Codex review, findings 7, 18, 19). |
| D-019 | 2026-11-09 | Owner-provided items (accounts, keys, go-aheads) are tracked in `docs/owner-checklist.md` and requested by the working agent at the plan step where each is first needed, not up front. | Owner 2026-11-09: "запиши это в требования проекта, мы это сделаем в процессе, пусть агент напомнит мне когда придет время". |
| D-020 | 2026-11-09 | Work is organised in six stages (`docs/stages.md`), each one OpenSpec change on the project schema `openspec/schemas/nearbee` and one pull request, through the cycle of `docs/process.md`: artifacts reviewed by another model family, implementation by a separate coding agent, acceptance and the quality cycle (native gate, OCR, cross-family review, security and test audits, security review, final review) by the integrator. | Owner 2026-11-09: every stage built in OpenSpec on a non-default setup, code by another agent, the coordinating agent accountable for the result and for the review cycle used in the owner's other projects. |
| D-021 | 2026-11-09 | Implementers are separate Claude Opus sessions (headless, chosen by the owner per stage); the integrator merges a stage on a clean cycle and green native gate without asking; the public repository https://github.com/itechmeat/nearbee was created by the owner the same day, so stages land as pull requests there. | D-025 | 2026-11-10 | One active apb run at a time across all served agents until per-hire git worktrees exist (S4). Intake, downloads and lifecycle reconciliation run whatever the slot; every apb start (first-time, rework, redo) waits for it, oldest first, and a waiting hire past its deadline is declined (`rejected` for a first-time hire never started on the market, `failed` for one already started there and for a rework or redo; refined 2026-11-10 in review round 2) A hires directory that cannot be listed completely holds the slot as well, and the same predicate keeps a hire with unsettled local work out of cleanup (refined 2026-11-10 in review round 3). | The runs share one apb workspace and its files; an unresolved start never proves that no run will land, so the safe side of a duplicate run is to hold the slot. Measured cost: a long run delays the next hire's start, its wall clock still runs (design 5, risk 1). |
